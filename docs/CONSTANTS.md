# CONSTANTS — provenance of every module-level constant in the shipped path

Generated from [`constant_provenance.json`](constant_provenance.json) by `scripts/constant_provenance.py --write`. **Do not edit this file by hand**; edit the JSON and run the script. The machine check is `tests/test_constant_provenance.py`.

## The question this answers

> Is any constant trained, fitted, tuned or calibrated on the wrong data?

Every module-level assignment in the shipped path carries exactly one tag below. The tag says what the constant may be justified by. `match` is the only class that is measured on this match, and it is **label-free**: no possession label, no hand label and no video enters it. No constant in the register is tagged with this match's ground truth or with the public 5 minutes, because no such constant exists (Q36/Q37).

## Tag vocabulary

| tag | meaning |
|---|---|
| `external (card)` | Set on external games/matches or by a recorded project decision and cited to a card (E/R/S/Q, D-0xx). Never selected on this match's ground truth, video or public window. |
| `published structure (D-007)` | Published by the organizers (D-007, FAQ, games.py, starter kit): half boundaries, kickoffs, match length, pitch, label encoding, asset names, frame rate. Structure is not evidence about what happened. |
| `physical/Laws` | A physical, physiological or Laws-of-the-Game fact (pitch geometry, sprint speed, walk/jog boundary, restart geometry); not fitted to any dataset. |
| `label-free match diagnostic` | Measured or fitted on THIS match's tracking with no labels and no video: ATD run-length quantiles, the low-pass widths, the simulator's fitted table, report-only measurements. This is the one class an auditor must read carefully. |
| `video-derived (report-only)` | An agreement rate or diagnostic computed against an automatic verdict derived from the broadcast video. Report-only: it never enters the build, a label path or a shipped decision. |
| `guard` | A defensive bound, canary, clip or pre-registered decision rule. It can fail the build or clip a value; it never selects a label and is never tuned on this match's answers. |
| `scaffold (not provenance)` | A filesystem path or a type alias: a computed object with no decision value. check() refuses this tag on a literal, so a number cannot be hidden here. |

## Scope

Twelve modules: the stage writers (`pipeline` holds no constant), the training-data simulator, `config`, and the two modules whose constants a shipped stage reads (`dproxy`, `ballfree`). Out of scope by design: loaders and providers (`data`, `external`, `evaluate`) hold parsing and cache-format constants, and the feature builder (`features`) holds perception constants; they are checked by their own tests and are proposed for a later card.

## Adding a constant

1. Add module-level assignment (any target form).
2. Add an entry to `docs/constant_provenance.json` under that module with `tag`, `source`, `why`.
3. If it is a string-keyed dict carrying numbers, add a field entry per key.
4. Run `python scripts/constant_provenance.py --write` then `make test`; an untagged name, an untagged field, a stale entry or a changed value fails `tests/test_constant_provenance.py`.
